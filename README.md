# MyNotion

**装在自己电脑上的 Notion。** 写页面、建子页、夹一张可筛选排序的表格，全文搜索中文，删掉的都能找回 —— 而你的笔记自始至终只是电脑里的**一个文件**。

▶ **[观看 37 秒演示](docs/assets/demo.mp4)**（文件在 `docs/assets/demo.mp4`，25 MB）

---

## 它能帮你做什么

- **像 Notion 一样组织想法**：一个页面套一个页面，侧边栏拖一下就改成子页；正文里 `/子页面` 就地建，`/数据库` 就地插表。
- **把杂乱事项变成能用的表**：待办、工时、状态、标签、日期、网址，随手加一列；按条件筛选、按字段排序，列宽拖一拖，行高跟着内容走。
- **找得到**：`Ctrl/Cmd + K` 输入中文词，直接命中正文里的字眼，不是只搜标题。
- **不怕手滑**：删页面、删表里的行都有退路 —— 10 秒内按 `Ctrl + Z` 立刻回来，早过了就去回收站恢复。
- **换电脑不折腾**：所有东西都在一个文件里，拷走就是完整迁移；备份不需要挑目录，一条命令出一份快照。
- 最重要的一点：完全本地，不用再忍受网络环境差的时候notion无法打开的问题

## 为什么要自己装一个

Notion 很好，但它的重心在云端：内容存在它的服务器上，功能按套餐解锁，换一台设备要先登录同步。MyNotion 反过来做：

- **数据是你的**。没有账号，没有云同步，没有遥测，也不会哪天因为"套餐调整"就少了一个你天天用的功能。
- **打开就是自己的东西**。它跑在你自己的电脑里，联网不是使用前提，也没有登录这一步。
- **想留就留，想走就走**。整份笔记就是硬盘上那一个文件，复制它就是完整备份；不喜欢了，把文件带走、把文件夹删掉，不需要向谁申请导出。
- **缺功能可以自己加**。它不是一个黑盒应用，而是一份完整、可读的源码：想让某个页面变成周报模板、想多一种字段类型，改得动，也看得懂改在哪。
- **它不打算替代 Notion**。需要多人实时协作、需要手机 App、需要别人给你分享链接的时候，请继续用那些工具；MyNotion 服务的是"我自己的东西，我自己保管"这一类需求。

## 特性

| 能力 | 说明 |
| --- | --- |
| 块编辑器 | BlockNote 默认块（段落/标题/有序无序列表/待办/代码/引用/分割线等）+ `/` 唤出中文命令菜单，菜单里额外有「子页面」「数据库」 |
| 页面树 | 无限层级子页面、拖拽改层级与排序、子页折叠（折叠状态本地持久化）、行内删除 |
| 子页面芯片 | `/子页面` 就地创建并嵌入；从侧栏删除子页时，父页正文里的芯片同步摘除，回收站恢复时按原位放回 |
| 数据库表格视图 | 页面内嵌表格。列为标题 + 可添加的 文本 / 数字 / 单选 / 多选 / 日期 / 复选框 / 网址，外加自动的创建时间列；支持筛选、排序、列宽拖拽、行高随内容自适应 |
| 撤销删除行 | 删除数据库行后 10 秒内 `Ctrl/Cmd + Z` 或点提示条即可恢复，超时则进回收站 |
| 中文全文搜索 | `Ctrl/Cmd + K`，SQLite FTS5 + trigram 分词，子串匹配绕开中文不分词问题 |
| 回收站 | 全部删除是软删（级联子树），可恢复也可彻底删除 |
| 备份 | `pnpm backup` 走 SQLite 在线备份 API，与正在进行的读写并发安全 |
| 自动保存 | 编辑器状态与上次快照差分，只提交变化的块（500ms 去抖），右上角有保存状态 |

## 快速开始

### 前置要求

| 依赖 | 版本 | 为什么必须 |
| --- | --- | --- |
| Node.js | **≥ 24**（实测 v24.21.0） | 同时依赖两项原生能力：`node:sqlite`（内置 SQLite，免装原生驱动）和 TypeScript type-stripping（服务端直接 `node src/index.ts`，不需要构建步骤） |
| pnpm | **12.x**（lockfile v9） | 仓库是 pnpm workspace，用 npm/yarn 装不出同一棵树 |
| 浏览器 | 支持 ES2023 的现代浏览器 | Chrome / Edge / Firefox 均可 |

装 pnpm 最省事的方式是 corepack（Node 自带）：

```bash
corepack enable && corepack prepare pnpm@12.11.2 --activate
```

### 三步跑起来（开发模式）

```bash
pnpm install
pnpm dev
# 打开 http://127.0.0.1:5173
```

`pnpm dev` 同时起两个进程：API 在 `:8791`（`--watch` 热重启），前端在 `:5173`（Vite dev server，`/api` 已配置代理，同源无 CORS）。首次启动会自动建 `data/` 目录和空库，无需任何初始化命令。

只有 `pnpm install` 这一步需要联网拉依赖；装完之后，整个应用和它的数据都在本地，断网可用。

### 一键启动（不想记命令）

- **Windows**：双击 `start-mynotion.cmd`
- **macOS / Linux**：`node scripts/launch.mjs`

它会探测 8791/5173 是否已在服务，**复用已在跑的进程、只补缺失的**，就绪后自动打开浏览器；关窗或 `Ctrl+C` 只停本次启动的进程，不会误杀你之前自己开的。

### 生产单进程（一个端口搞定）

```bash
pnpm serve        # = pnpm build && pnpm start
# 打开 http://127.0.0.1:8791
```

`apps/web/dist` 存在时，服务端会用 `serveStatic` 托管前端产物，前后端同源。

> **Windows 已知问题**：Vite 8 底层用 rolldown，其平台原生 `.node` 绑定在开启了 Smart App Control 的 Windows 上会被拦截，`pnpm build` 可能报加载原生模块失败。三个选择：① 日常直接用 `pnpm dev`，不需要构建；② 在 CI 或 Docker 里构建，产物拷回本地；③ 手动 `pnpm add rolldown@1.2.14`（版本必须与 `pnpm-lock.yaml` 里的 rolldown 一致），让 Vite 走 bundled JS 回退路径。详见 [docs/known-issues.md](docs/known-issues.md)。

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 并行起 API（`--watch`）与前端（Vite），日常开发用这个 |
| `pnpm build` | 构建前端产物到 `apps/web/dist` |
| `pnpm start` | 单进程服务模式（有 `dist` 就同时托管前端） |
| `pnpm serve` | `build` + `start` |
| `pnpm typecheck` | 三个包各自 `tsc --noEmit`（严格模式 + `noUncheckedIndexedAccess`） |
| `pnpm backup [目标路径]` | 生成 `data/backup-YYYYMMDD.db`，或指定路径 |
| `node scripts/launch.mjs [--no-open]` | 一键启动，`--no-open` 不自动开浏览器 |

## 配置

全部走环境变量，没有配置文件，默认值即可跑：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `PORT` | `8791` | API / 生产模式服务端口 |
| `DATA_FILE` | `<仓库根>/data/mynotion.db` | SQLite 文件位置，指到别处即可换库或做多实例 |

前端 dev 端口固定在 `apps/web/vite.config.ts`（`5173`，`host: 127.0.0.1`）。

## 数据与备份

- 整个工作区是 `data/mynotion.db`（+ WAL/SHM 两个附属文件）。**迁移 = 拷贝这个文件**；重装 = 换一个新文件。
- **服务在跑时别只拷 `.db`**：最近几秒的写入还在 `-wal` 里，要么停服后连三个文件一起拷，要么直接用 `pnpm backup`（SQLite 在线备份 API，与并发读写安全）。
- 删除一律是软删：`deleted_at` 打标，回收站里可恢复；"彻底删除"才真删行，块的物理清理靠外键 `ON DELETE CASCADE`。
- `data/` 与 `*.db` 已在 `.gitignore` 里，你的笔记不会被提交。
